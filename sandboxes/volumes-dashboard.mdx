---
title: "Manage volumes in the dashboard"
description: "Browse, upload, and move sandbox volume files from the Porter Dashboard"
---

Every sandbox volume has a file browser in the Porter Dashboard. Use it to inspect what sandboxes have written, upload files into a volume before a sandbox mounts it, and reorganize files — without dropping into the SDK or CLI.

<Warning>
Sandboxes are in a private beta. Please reach out to us at support@porter.run or over Slack if you are interested in joining.
</Warning>

## Open a volume

In the Porter Dashboard, open the **Add-ons** tab and select **Sandbox file storage** for your cluster to see every volume on it, then click a volume to open its detail page. The **Files** tab is selected by default.

<Note>
Browsing files needs a cluster running sandbox-api `0.1.41` or newer, and uploading and moving need `0.1.42` or newer. On a cluster that has not picked up the write routes yet, the file browser appears without the upload and move affordances; on older releases still, the Files tab is hidden entirely.
</Note>

## Browse files

The Files tab lists the volume's contents as a tree, directories first. The server walks the tree up to an entry budget; a directory it could not fully read is marked truncated — expand it to list the rest.

## Upload files

Drag files from your computer and drop them onto the tree. A file dropped onto a directory row uploads into that directory; dropped on empty space, it lands in the volume root. Parent directories are created as needed, and an existing file at the path is replaced.

<Frame>
  ![Dragging a file onto the volume tree to upload it](/images/sandboxes/volume-upload.gif)
</Frame>

Uploads follow the same rules as [SDK](/sandboxes/sdk/typescript/volumes#write-a-file) and [CLI](/sandboxes/cli#porter-sandbox-volume-write) writes: each write is atomic, so an interrupted upload leaves the previous contents in place, and a single file is capped at 1 GiB. Write larger files from inside a sandbox that mounts the volume.

## Move or rename files

Drag a row onto a folder to move it there. A directory moves with everything under it, and nothing is overwritten — a move onto a path something already occupies is refused.
